## Initial Integration Plan

### Current Tech Stack

1. Tech Docs & Architecture: Notion

## Auth & User Management

### Frontend

- Build signup/login forms.
- Collect email, password, name, health affiliation, and role.
- Handle loading, success, and error states.
- Protect authenticated pages.

### Backend

- Connect auth provider.
- Store user profile and role.
- Return current user/session data.

### Workflow

1. User signs up or logs in.
2. Frontend sends auth request.
3. Auth provider validates credentials.
4. User role and profile are created or retrieved.
5. Session becomes available to the frontend.
6. Protected frontend pages and backend endpoints use that session.

## Listing Creation & Management

### Frontend

- Build listing detail page.
- Build host create/edit listing form and check role.
- Display rules for hosts only.
- Handle loading, success, and error states.
- Display uploaded photo previews before saving.
- Create form fields for title, description, location, price, availability, photos, neighborhood info, and local recommendations.
- Neighborhood info and local recommendations might be generated by the app if geodata is already available.

### Backend

- Create listing create/read/update/delete endpoints.
- Create database schema for listings.
- Validate required listing fields.
- Add host-only permission checks.
- Handle listing status.
- Store photo URLs and connect them to the correct listing.

### Workflow

1. Host opens create listing form.
2. Frontend collects listing details.
3. Frontend sends data to backend API.
4. Backend validates host permission and required fields.
5. Backend saves listing through Prisma/PostgreSQL.
6. Frontend displays success or error state.

## Healthcare Affiliation Verification

### Frontend

- Add a verification status section to the renter profile.
- Add a "Start verification" button that requests a Veriff session.
- Redirect the user into the Veriff verification flow.
- Show verification states.
- Disable or warn on renter-to-host contact if verification is required.
- Send out an email for verification.

### Backend

- Create an endpoint to generate a Veriff verification session for the current user.
- Store verification records in the database.
- Add an endpoint to receive Veriff status updates and email verification to the app owner for healthcare verification.
- Return verification status.

### Workflow

1. Renter signs up or logs in.
2. Frontend shows verification prompt and emails a verification link.
3. Renter clicks "Start verification" or the link.
4. Frontend requests Veriff session from backend.
5. Backend creates Veriff session and stores session ID.
6. Frontend redirects renter to Veriff flow.
7. Veriff completes review and sends webhook to backend.
8. Backend also sends the data to the owner for healthcare verification.
9. Backend updates renter verification status.
10. Frontend displays healthcare-affiliation verification.
11. Verified renter can contact hosts if gating is enabled.

## Search & Discovery

### Frontend

- Build the listing search page.
- Build listing cards that use the backend's listing summary response.
- Build listing detail pages.
- Add loading, empty, and error states for search results.
- Add filter controls for city, nearby hospital, price, dates, and listing type.
- Add the URL query string for sharing.

### Backend

- Create a search/listings endpoint.
- Return a listing card response for search results.
- Return full listing detail data for the listing detail page.

### Workflow

1. Renter opens search page.
2. Frontend reads filters from URL or default state.
3. Frontend calls listing search API with query parameters.
4. Backend validates filters and queries PostgreSQL.
5. Backend returns matching listing summaries.
6. Frontend renders listing cards.
7. Renter clicks a listing.
8. Frontend requests listing detail by ID.
9. Backend returns full listing detail.

## Messaging / Inquiry System

### Frontend

- Add an inquiry/contact form on the listing detail page.
- Show verification requirements before a renter can submit an inquiry.
- Build a messaging view.
- Show notification status labels for new messages.

### Backend

- Validate that the renter is authenticated and allowed to contact the host.
- Validate that the listing exists and is active.
- Create inquiry endpoints.
- Store inquiry records.
- Trigger future email or in-app notification after a new inquiry is created.

### Workflow

1. Renter opens listing detail.
2. Frontend checks auth and verification status.
3. Renter submits inquiry form.
4. Frontend sends inquiry request to backend.
5. Backend validates renter, host, listing, and verification rules.
6. Backend saves inquiry or message thread.
7. Backend returns inquiry confirmation.
8. Frontend shows success state.
9. Host sees inquiry in dashboard or receives notification.

## Admin & Moderation Tools

### Frontend

- Build an admin dashboard protected by Admin role access.
- Add a listing approval queue with approve, reject, and request changes actions.
- Add a user verification management view.
- Add basic moderation controls for hiding listings or flagging users.
- Show listing status labels.

### Backend

- Add Admin role permission checks to admin-only endpoints.
- Create endpoints for listing approval, listing rejection, and listing moderation.
- Create endpoints for viewing and updating user verification records.
- Store moderation status and audit fields.
- Prevent unapproved or hidden listings from appearing in public search.

### Workflow

1. Host submits listing.
2. Backend saves listing with pending status.
3. Admin opens approval queue.
4. Frontend requests pending listings.
5. Backend returns listings requiring review.
6. Admin approves or rejects listing.
7. Backend updates listing status and audit fields.
8. Approved listings appear in search.
9. Rejected or hidden listings stay out of public results.

## Payments (Stripe)

### Frontend

- Add payment entry points.
- Show booking or transaction summary before payment begins.
- Display payment states: not started, pending, paid, failed, refunded.

### Backend

- Create an endpoint to initialize a Stripe Checkout Session.
- Validate renter, host, listing, amount, and transaction eligibility before creating payment.
- Store transaction records with Stripe IDs and internal status.
- Add a Stripe webhook endpoint for payment success, failure, refund, and dispute events.
- Review whether Stripe Connect is needed for host payouts.

### Workflow

1. Renter and host agree to proceed.
2. Frontend requests payment initiation.
3. Backend validates listing, renter, host, and amount.
4. Backend creates Stripe Checkout Session or PaymentIntent.
5. Frontend redirects renter to Stripe or renders secure Stripe payment UI.
6. Stripe processes payment.
7. Stripe sends webhook event to backend.
8. Backend updates transaction status.
9. Frontend shows payment result to renter and host.
